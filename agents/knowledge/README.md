# Knowledge Agent: retrieval-augmented generation

The input documents remain plain UTF-8 text. Chunking and vectors are generated by the pipeline; do not replace source text with embeddings.

## Pipeline
1. Load visible `.txt` and `.md` files recursively from `data/`. Hidden files, unsupported formats and symbolic links are excluded. The corpus is limited to 100 files, 2 MB and 2,000 chunks.
2. Split at Markdown headings, then into windows of up to 1,200 characters, preferring paragraph/line/word boundaries. Adjacent windows overlap by 200 characters. Each chunk has a stable ID, relative file name, heading and source line range. Sizes are characters, not model tokens.
3. Embed document chunks with Gemini `gemini-embedding-001`, `RETRIEVAL_DOCUMENT`, 768 dimensions. Vectors are normalized and cached in SQLite. Batches contain at most 32 chunks. Unchanged content is reused across restarts; changed or removed files invalidate the corresponding cached vectors. A model/config namespace prevents reuse across incompatible embeddings.
4. Embed the question with `RETRIEVAL_QUERY`. Rank chunks by cosine similarity, filter below the threshold and suppress near-duplicate windows. Default: top 4 chunks, minimum cosine score 0.45. This threshold is a configurable heuristic, not a probability; tune it against your own questions, including Vietnamese questions.
5. Pass only selected chunks to Gemini for grounded generation. A system instruction treats documents as untrusted evidence, prohibits outside knowledge and requires numbered citations. The server rejects missing or out-of-range citations. Citation syntax validation does not prove the answer is factually supported; evaluate grounding on your own documents.
6. Return the answer plus `[1] project_info.txt, lines 3-6`. If nothing meets the threshold, return exactly `{"status": "not_found"}`. The coordinator can then use its existing general-knowledge fallback. Grounded answers bypass the summary rewrite to retain their citations.

Both A2A (via the `answer_from_documents` tool) and the internal `/run` endpoint use the same engine. `search_local_docs` now returns semantic retrieval results and metadata as JSON; it no longer accepts synthetic `mock_content`. Use a temporary data directory and an injected backend for tests.

## Add documents and build the index
Place UTF-8 `.txt` or `.md` files beneath `agents/knowledge/data/`. Only put material you are allowed to send to Google here. PDFs, DOCX, OCR, access control per document and external vector databases are not included.

From the repository root:

```sh
docker compose up -d --build agent-knowledge agent-coordinator
# Optional: build/cache document vectors before the first chat request.
docker compose exec agent-knowledge python ingest.py
```

Without prewarming, the first query builds the index lazily and may take longer than the gateway timeout on a large corpus. Subsequent requests reuse document vectors; each question still needs one query embedding and grounded generation. The A2A wrapper may perform additional LLM tool-routing calls.

The source data mount is read-only. The named `knowledge-rag-cache` volume preserves embeddings across container recreation. To purge cached embeddings, stop the knowledge service, remove that specific Docker volume (find its project-prefixed name with `docker volume ls`), then recreate the service. Do not use a blanket volume deletion command if other service data must be preserved.

Local execution from this directory also works after installing `requirements.txt` and exporting `GEMINI_API_KEY`: `python ingest.py`, then `python agent.py`. Files named `.env` are not loaded automatically by these scripts; Compose supplies the environment from the project root.

## Settings
| Variable | Default | Meaning |
| --- | --- | --- |
| `RAG_DATA_DIR` | `data/` next to agent.py | Trusted document directory |
| `RAG_CACHE_PATH` | `.rag-cache/vectors.sqlite3` | Persistent embedding cache |
| `RAG_CHUNK_SIZE` | `1200` | Maximum characters per window |
| `RAG_CHUNK_OVERLAP` | `200` | Character overlap, less than half the size |
| `RAG_TOP_K` | `4` | Retrieved chunks, from 1 to 8 |
| `RAG_MIN_SCORE` | `0.45` | Minimum cosine similarity |
| `RAG_GENERATION_MODEL` | `gemini-2.5-flash` | Grounded answer model |

Set the chunk/retrieval variables in the root `.env` for Compose. `RAG_GENERATION_MODEL` is also forwarded to the knowledge container.

SQLite stores normalized vectors and content hashes, not original text, queries or generated answers. Embeddings can still reveal information about the source: treat the cache as sensitive. The entire indexed corpus is sent to Google's embedding API during first indexing, and changed chunks are sent on subsequent builds; this is broader than only sending the snippets selected for an answer. Provider data handling follows your Gemini API terms and account settings.

## Tests
From this directory:

```sh
python -m pytest -q
```

Tests inject deterministic fake embeddings and generated responses: chunk overlap, line numbers, semantic retrieval, cache persistence/invalidation, no-match handling, citation validation and corpus bounds. They never use your real API key, send documents or consume Gemini quota. Live retrieval quality and latency still require evaluation with your own corpus and provider account.
